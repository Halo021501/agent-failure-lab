新增 SQLite 提交意图与一致性迁移备份；文件原子替换、产物索引和提交事件联动恢复。原子队列覆盖全库，不再只检查最近 100 实验。认领、取消、终态转换及令牌清理有测试。运行列表按案例/种子稳定排序；回归脚本明确选择每案首个种子，避免相同创建时间造成漏选或重复回放。

评测器版本为 facts-and-citations-v3：保留四字段组，另按单项事实、遗漏、错误和所需引用计数；重复事实/引用不能提高分数。执行失败但已提交报告时仍评测实际报告的事实和引用；处置通过与完整成功强制为 false。没有报告的自然结束失败才按期望事实计遗漏，避免把回执丢失误说成报告事实缺失。模型 partial 的依据通过评测器检查实际交付内容，框架不会替模型解析或修正请求。

报告改为中文可读内容，引用打开本次读取的原文与定位，再跳转对应事件。事件增量追加，不替换正在阅读的节点；刷新保留运行选择和展开状态。模型元数据与未知费用有独立展示；旧后端会禁用新模型入口并提示重启。

Windows Python 3.12.5 的 monotonic 时钟使用 GetTickCount64，精度 15.625 毫秒，曾漏判短工具超时。执行期限与耗时已统一改用 QueryPerformanceCounter 的 perf_counter。短工具超时检查重跑通过。单案墙钟预算也包含资料快照核验和初始化，不能借初始化绕过时限。

## 模型实现与费用边界

已实现两个提示词、三个严格工具、Responses 循环、输入 Token 预检、模型调用 ID 映射、可见请求/响应、供应商所报模型和用量。配置只保存模型名称/预算/环境变量名；密钥不进入文件或日志。当前未配置模型名称，未读取到 OPENAI_API_KEY。

多工具调用按顺序执行；非法参数返回给模型，不自动修正。框架不自动重试网络，不补写报告。单案输入/输出/模型/网络预算、整批原子预留及取消均有实现。未知用量保守预留并停止后续生成，价格与费用为 unknown。

整组模型比较要求每个案例已发起生成尝试，以及供应商所报模型版本一致。预算提前耗尽导致未发起请求的案例，会使模型覆盖不完整，禁止正式提升结论。严格回放保持本次零执行；工具回放产生新的模型请求与用量。上述模型行为目前由模拟供应商验证，不能替代真实 API 验收。

## 已知限制

本地文件工具只在边界合作取消，无法强制打断卡住的系统 I/O。模型取消只证明本地停止等待，供应商端可能继续执行或计费；未取得用量时保留保守预算。Token 上限无法替代供应商账户消费限制，预检/响应上限若被供应商超出，会补记实际值并停止。

响应条数分页已实现，但大型内容尚未分块，全部内容仍存事件。人工破坏事件 JSON 时部分浏览入口可能报错，完整性层会阻止其评测计分。加密推理内容只在内存中携带，日志不保存隐含推理，因而无法重建隐含推理过程。

模型重试、取消及真实供应商契约仍需真实或 HTTP mock 验收；离线脚本和模拟用量只证明框架行为。未来选择滚动模型别名时，供应商所报名称相同也不保证内部权重永远固定，严谨实验需使用可用的固定版本。
