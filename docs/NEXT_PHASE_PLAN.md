## 3. W1：记录完整性与失败回放（P1）

### 实现内容

- 给运行增加独立的完整性状态：`valid / invalid / unverified`，同时记录检查时间、原因和证据哈希。保留历史执行终态与历史评测，避免把后来损坏的文件改写为 Agent 当时执行失败。
- 汇总、比较、导出和详情使用同一完整性检查入口。损坏记录不计为成功；显示完整性异常和受影响数量，整组实验不能产生正式提升结论。旧记录缺少封存信息时标为 unverified，不默认为已核验。
- 区分“历史评测”与“当前可采信的评测”。校验缓存绑定产物/轨迹哈希与文件状态；读取异常立即失效，正式比较与导出强制复核。哈希用于一致性检查，不宣称能防止数据库和文件被一起恶意修改。
- 将报告 JSON 作为权威产物，Markdown 作为可再生成的展示文件。引入提交意图及恢复协议：登记意图 → 写临时文件并同步 → 原子替换 → 在同一数据库事务登记索引和提交事件。恢复时处理每个中断窗口和孤立文件；同一键、同一内容最多产生一次提交事件。
- 回放记录显式保存写入是否提交、提交哈希及回执结果。工具回放先在新运行空间重现已记录的提交，再交付录制的成功或错误；不能把“收到超时”推断为“未写入”。无产物的失败运行也能做严格记录回放，并保留“未提交”的事实。
- 在创建回放任务前检查录制完整性；执行初始化失败进入明确终态，不遗留空实验或 pending 记录。
- 保存完成时的执行轨迹封存信息；后续完整性检查和恢复审计使用独立审计记录，不能追加到已封存轨迹导致正常记录校验失效。
- 引入显式数据库 schema 迁移。迁移前用 SQLite 一致性备份保存数据库，并保留产物；迁移失败可恢复。旧评测、原轨迹及父运行关联不覆盖。

### 验收

1. 修改、删除报告或修改事件后，详情、汇总、比较、JSON/CSV 导出给出一致结果，无旧的成功标签。
2. F-D04 和 X03 在两种策略下覆盖“提交前失败”和“提交后丢回执”；工具回放的产物存在性、哈希、幂等键和提交次数与原记录一致。
3. 分别在提交意图、文件替换、索引提交等边界注入进程中断；重启后只有一次可用提交或明确的未提交状态，不存在静默丢失。
4. 旧数据库升级后可读、历史轨迹不变；备份恢复流程通过。未封存或缺失产物的历史失败记录状态如实展示。

## 4. W2：指标与实验比较（P1）

### 指标口径

| 指标 | 下一版定义 |
| --- | --- |
| 执行进度 | 分开列出计划、排队、运行、正常结束、失败、预算耗尽、取消、中断、完整性异常数量 |
| 完整成功 / 处置通过 | 在已核验且自然结束的执行中统计；执行错误和预算耗尽保留在分母，未运行取消和服务中断单独展示；存在缺失执行时注明整组实验不完整 |
| 条件恢复率 | 仅统计已核验、自然结束、实际触发可恢复故障的执行；完整成功作为恢复，不将正确 partial 算作恢复 |
| 故障覆盖 | 分别给出案例触发覆盖与预定故障规则触发覆盖，防止只触发组合故障中的一条就显示全部覆盖 |
| 耗时 | 有真实起止时间的已执行终态才进入分布；排队耗时、实际执行耗时、模拟故障秒数分开；工具回放单独统计 |
| 事实 / 引用 | 现有四组事实指标明确改名为“字段组通过”；增加逐事实正确、遗漏、错误和引用覆盖计数。自然结束但无有效报告按缺失计入，不因没有 evaluation 而消失 |
| 缺口 | 合法未知值与合法空列表分别验收；未知不作为正确事实奖励；核对缺口指向的实际错误或损坏响应证据 |
| 成本 | 脚本显示 0；模型分开显示已知 token、未知用量和估算费用；缺少用量或价格时显示 unknown，不能置 0 |

不通过删除失败或取消样本制造提升。正式比较要求双方计划中的 `(case_id, seed)` 全部完成、无重复配对、无取消/中断/完整性异常；不满足时只显示完成进度和已观察结果，隐藏提升幅度和 improved/regressed 标签。所有无分母指标显示 N/A。

### 可比性与版本

- 将现有整份代码指纹拆分为实验框架、工具契约、评测器、策略/提示词、模型适配器版本，记录依赖及运行环境摘要。
- 比较检查套件及资料哈希、框架/工具/评测版本、模式、预算、案例与种子、执行完整性。策略、提示词或模型可以作为明确声明的比较变量，其他条件保持一致；不能简单要求全部源码相同而阻止策略比较。
- 脚本与模型、fresh_run 与 tool_replay 分开展示；trace_replay 保持排除。工具回放只支持严格匹配的决策路径，发生调用分歧如实记录 replay_mismatch，不据此推断新策略在真实工具上的能力。
- 新评测使用版本化结果。增加“重新评测”入口，追加新评测及输入哈希，保留历史版本；严格回放仍展示原评测。未统一到同一评测版本的两组实验不可正式比较。
- 区分网关拒绝重复/旧响应的工程保障与 Agent 自己采取的恢复动作，报告和导出分别归因。

### 验收

1. 一次成功加三次未启动取消：已执行通过率为 100%，执行覆盖为 1/4，耗时取实际一次执行，正式对比禁用。
2. 自然结束的工具错误、无报告和预算耗尽不会从成功率、事实及引用覆盖统计中消失。
3. 预算或框架版本不同、配对重复、未完成和完整性异常均给出具体原因，不显示提升标签。
4. 同一框架下仅更换策略可正常比较；重新评测保留旧结果；JSON、CSV 和网页口径一致。

## 5. W3：执行控制与数据规模（P1 / P2）

- 回放与普通实验统一为后台任务：先校验并原子创建实验/运行，接口返回 `202 + experiment_id + run_id`，执行通过队列推进。
- 全库查询排队/运行数量；在锁或事务内同时检查容量与预留新增数量，不能只检查当前数量是否超过上限。保持单执行工作者的默认行为。
- 使用明确状态转换和条件更新认领任务，覆盖“取消与启动竞争”，避免取消后的记录被改回 running。完成后释放取消令牌，重启不自动续跑。
- 实时保存工具/模型调用数、当前步骤和预算消耗，进度不等到结束才更新。
- 实验列表、运行列表、事件使用游标和分页；事件接口设置上限，前端按 `after_seq` 获取新增事件。
- 明确工具截止时间与取消能力。v0.2 保留本地同步工具在调用边界合作取消的限制；v0.3 的模型网络 I/O 使用可取消的异步请求和硬截止时间。取消本地等待不能承诺远端请求没有被计费。
- 补齐不存在资源的 404、参数错误、队列满和回放不匹配的稳定错误码及中文说明。

验收：后台排队时回放请求仍在本机 1 秒内返回任务 ID；并发提交不突破 600 次待执行容量；取消与启动竞争不产生反向状态跳转。100 个以上实验可分页检索。300 次运行与 1 万条事件的固定样本下，API 每页有上限，界面持续可操作，记录实测时间与机器条件。

- 默认报告展示版本、功能、未解决问题、测试统计和缺口，用中文标签；原 JSON 保留在折叠的调试视图。
- 每项事实可点击来源，定位到本次实际读取的内容、行/JSON 条目/CSV 行，同时展示哈希和对应读取事件；来源内容以文本显示。
- 时间线突出首次故障、重试、备用资料切换、产物提交和终态。轮询仅追加新增事件，保留展开状态、当前滚动位置和选中的运行，切换运行时丢弃过期响应。
- 区分“已执行进度”“整组完整性”“历史评测”和“当前可用结论”；比较页先展示可比性原因，再展示允许使用的结果。

## 7. W5：真实模型接入（P1）

### 实施边界

首轮实现一个具备结构化工具调用的供应商适配器。供应商和模型由本地配置指定；编码前核验该接口的官方文档并锁定依赖。当前不预选模型名称、价格或推断不同供应商完全兼容。

配置包含供应商、模型、接口地址、凭据环境变量名称和预算。界面只显示配置状态与非敏感参数；凭据、认证头不进入事件、网页或导出。未配置时模型任务显示明确原因，离线功能继续可用。

### 执行与记录

- 模型只能访问与脚本相同的三个资料/报告工具。提示词只提供任务、报告/引用契约、公开工具定义和预算，不含真值、故障计划或期望恢复答案；对适配器的请求载荷做边界测试。
- 保存提示词版本及哈希、模型/接口参数、可见响应、工具调用 ID、参数、交付结果、实际 token 用量和耗时，不要求或保存隐藏思维链。
- 执行循环覆盖正常响应、未知工具、非法参数、多工具调用、无调用、提前结束和预算耗尽。首轮按响应顺序串行处理工具调用；非法调用返回明确工具错误并计入动作预算，不替模型自动补参数或改报告。
- SDK/传输层关闭隐式重试；恢复动作归属于策略并写入记录。模型请求失败与工具注入故障分开计数，不能把网络错误当作某个工具故障的恢复。
- 加入每次请求超时、整体截止时间、工具/模型请求上限和输入/输出 token 上限。模型请求开始前预留最大输出 token 额度，超限停止；未知用量单独标记。供应商不支持所需硬上限时明确能力限制。
- 在途请求可以取消，取消后不提交新工具动作；远端是否已受理保留为未知。模拟慢响应验证本地请求等待在取消后 2 秒内退出。
- 用最小任务提示词与有限恢复提示词做 A/B，保持工具、评测和预算相同。报告缺口依据实际工具错误或原始损坏响应验证，不能依赖模型自述“我已经解析失败”。
- 工具回放使用录制工具结果但重新请求模型，记录真实模型用量；严格记录回放仍为零调用。模型模式不得沿用脚本中的 `model_calls=0` 或旧代码版本标记。

### 验收

先用本地模拟适配器覆盖错误、token、取消和多调用，再在配置完成后运行 6 个代表案例：N01、F-T01、F-M01、F-S01、F-D04、F-M04。检查真实请求数、工具行为、输出引用、预算和终态。不设置“模型必须全部成功”的门槛；失败有完整证据才算接口工程验收完成。

## 8. W6：留出评测与真实结果（P2）

- 原 30 案例保持为固定回归套件，不就地修改 v1。保存不可变套件快照和公开资料内容，真值作为独立评测输入，不进入模型快照；旧运行可绑定原资料版本回放。
- 增加独立的 12 个留出案例：正常资料变体 2、暂时超时 2、缺失/备用 2、格式/空结果 2、重复/回执丢失 2、组合且不可恢复 2。采用新版本、新事实、新文件排列及不同触发次数。
- 优化提示词前固定划分、案例及评测版本；留出真值只供验收。若根据留出失败继续修改提示词，该套件改为开发集并重新建立留出集。
- 固定模型、参数和预算，两提示词分别运行回归集 30×3 次、留出集 12×3 次，共 252 次计划执行。每次请求和 token 上限覆盖整组；达到总预算先停止并报告未完成覆盖，不将部分结果发布成完整比较。
- 先用 6 案例的实测用量估算批量消耗，界面显示计划执行次数、token 上限和已知费用；价格无来源时保留 unknown。
- 记录逐案结果、配对变化、失败类型、恢复动作、正确 partial、token/耗时及重复运行波动。确定性故障种子用于配对，不宣称固定种子能控制外部模型随机性；脚本的三次相同轨迹也不代表模型稳定性。

交付真实实验报告及机器可读数据。结果可以没有提升；结论必须限定到该模型版本、提示词、套件和预算。若缺少可用模型配置，W5 模拟适配器验收与留出套件先交付，真实实验保持待完成状态。
